BIP-360: Bitcoin's First Quantum Defense

Pay-to-Merkle-Root (P2MR) is the most concrete proposal for quantum-hardening Bitcoin. Authored by Hunter Beast, Ethan Heilman, and Isabel Foxen Duke, it's currently in Draft status (v0.11.0).

What BIP-360 does: Creates a new output type (SegWit v2, bc1z addresses) that removes the key path spend from Taproot. Your public key is never exposed on-chain, protecting against long exposure attacks.

How P2MR Works

  • Commits to the Merkle root of a script tree (like Taproot) but without an internal public key
  • All spends go through script path — no key path spend means no exposed public key
  • Compatible with existing tapscript and OP_SUCCESSx upgrade path
  • Soft fork — non-upgrading nodes treat it as anyone-can-spend
  • Sets the stage for future post-quantum signature opcodes

Technical Advantages

Immediate Benefits:
  • Protection against long exposure attacks for new transactions
  • No dependency on unproven post-quantum cryptography
  • Uses existing Bitcoin script capabilities
  • Backward compatible — doesn't break existing functionality
  • Optional adoption — users can choose to use bc1z addresses

Current Limitations

What P2MR doesn't solve:
  • Larger witness size than P2TR key path spends (always script path)
  • Less privacy — always reveals you're using a script tree
  • Only protects against long exposure — short exposure still needs PQ signatures
  • Doesn't help already-exposed P2PK or used Taproot addresses
  • Still requires consensus activation

Current Status

BIP-360 remains in Draft v0.11.0 status as of February 2026. The proposal is under active community review on the bitcoin-dev mailing list, with ongoing discussion about implementation details and activation timeline.

Step 2: Post-Quantum Signatures

The ultimate protection requires integrating NIST-standardized post-quantum signature schemes directly into Bitcoin script. This would protect against both long and short exposure attacks.

Leading candidates:
  • ML-DSA (Dilithium): NIST standard, ~2.4KB signatures, lattice-based
  • SLH-DSA (SPHINCS+): Conservative choice, 7.8-50KB signatures, hash-based
  • Hybrid approaches: Classical + post-quantum for belt-and-suspenders security

The technical path exists through BIP-360's OP_SUCCESSx mechanism, which reserves opcode space for future script upgrades without requiring a hard fork.

A single post-quantum signature could be 40–800× larger than a Schnorr signature. This creates significant challenges:

Impact on Bitcoin

Scaling Challenges:
  • Block space: Fewer transactions per block, higher fees
  • Storage: Blockchain size growth accelerates dramatically
  • Bandwidth: Node synchronization becomes more expensive
  • Validation: Signature verification computationally intensive
  • Mobile wallets: Light clients struggle with large signatures

Potential Solutions

Signature Aggregation: Combine multiple signatures into one larger signature, amortizing the size overhead across many inputs. This is already used in Bitcoin for Schnorr signatures and could be adapted for post-quantum schemes.
Compression Techniques: Research into compressing post-quantum signatures without compromising security. Some schemes offer size/security tradeoffs.
Hybrid Signatures: Use classical signatures for most cases, post-quantum only when quantum threat is imminent. Requires careful threat monitoring.
Layer 2 Solutions: Move post-quantum signatures to Lightning Network or other L2s, using classical signatures for on-chain settlement.

What's Missing

  • Consensus on urgency: Community hasn't reached agreement on timeline pressures
  • Legacy migration plan: No clear proposal for vulnerable existing UTXOs
  • Emergency procedures: Informal plans for rapid activation if quantum threat accelerates
  • Economic analysis: Limited study of fee/scaling impacts from large signatures
  • Standards coordination: Need alignment with broader crypto ecosystem migration

The Strategic Challenge

Bitcoin faces a unique challenge in quantum preparedness:

The Consensus Dilemma: Bitcoin requires broad consensus for protocol changes, but quantum threats create asymmetric risk. Acting too early introduces complexity for uncertain benefits. Acting too late may leave the network vulnerable. The community must balance preparedness with conservative engineering.
The Goldilocks Approach: Current strategy appears to be layered preparation — start with low-risk changes like BIP-360, continue research on post-quantum signatures, monitor quantum developments closely, and maintain ability to accelerate if needed.
