Postquant Labs: Quantum-Safe Bitcoin Wallet via Arch Network

April 28, 2026 — A new wallet delivers post-quantum signature protection for Bitcoin without requiring a soft fork, using Arch Network as a verification layer.

← Back to Timeline

What Happened

Postquant Labs launched a Bitcoin wallet that uses Arch Network — a Bitcoin-native execution layer — to deliver post-quantum cryptographic signature protection without requiring any change to Bitcoin's consensus rules. The project sidesteps both Jameson Lopp's controversial freeze proposal and Paul Sztorc's hard fork approach, offering an opt-in solution that works today.

Rather than waiting for a Bitcoin soft fork (like BIP-360) to add quantum-resistant signature types natively, Postquant Labs uses Arch Network's smart contract capabilities to verify post-quantum signatures off-chain while settling normally on Bitcoin's base layer. Users can protect their funds immediately without needing consensus from the broader network.

How It Works

The approach leverages Arch Network as a verification bridge:

  • Post-quantum signatures are generated client-side using NIST-approved algorithms (likely ML-DSA/Dilithium or SLH-DSA/SPHINCS+)
  • Arch Network verifies these signatures in its execution environment, acting as a trust layer
  • Bitcoin settlement happens normally — the base layer sees standard transactions
  • No fork required — works within Bitcoin's existing protocol constraints

This is architecturally distinct from StarkWare's QSB (which uses hash-to-sig puzzles at $75–$150 per transaction) and from BIP-360 (which requires a consensus-level soft fork). Postquant Labs offers a middle path: post-quantum security through an overlay network, with Bitcoin-native settlement.

Why It Matters

The Fork Deadlock: Bitcoin's governance makes consensus changes slow — Taproot took years. With the quantum timeline compressing (Caltech/Oratomic's 10K–20K qubit threshold, Google's 2029 deadline), solutions that don't require forks are increasingly valuable. Postquant Labs joins StarkWare's QSB and Lightning Labs' escape hatch as a "don't wait for consensus" approach.

Context: The Freeze vs. Build Debate

The Bitcoin quantum defense community has split into two camps:

  • Freeze camp (Lopp, Papathanasiou): Freeze quantum-vulnerable UTXOs before attackers can steal them — preemptive but controversial (property rights concerns)
  • Build camp (StarkWare, Postquant Labs, BTQ): Build quantum-resistant solutions now so freezing is unnecessary — opt-in but introduces new trust assumptions

Postquant Labs explicitly positions itself as an alternative to both freezing and hard forking, offering a pragmatic middle ground that's available immediately.

Trade-off: No-fork solutions like Postquant Labs introduce additional trust assumptions (Arch Network's security model) that don't exist in native Bitcoin transactions. Users must evaluate whether the quantum protection benefit outweighs the added complexity and potential attack surface of the overlay network. This is the fundamental tension: sovereignty vs. speed of defense.

What's Next

The proliferation of no-fork quantum defense solutions signals that the market isn't waiting for Bitcoin Core consensus. Multiple competing approaches are now live or nearly live, creating a de facto quantum defense ecosystem even without protocol changes. The question is whether these overlay solutions will be "good enough" — or whether a native BIP-360 soft fork remains essential for long-term security.
